# Architecture Decision Records: AquaGuard AI

This document logs the critical design decisions made during the architectural planning of AquaGuard AI.

---

## ADR 01: Object Detection Model Strategy

### Context
We require an object detection model (Task B) capable of identifying floating plastic objects in images and video feeds. The primary constraints are local inference latency (< 200ms per frame on CPU) and high classification accuracy across multiple classes (such as bottles, bags, Styrofoam).

### Alternatives Considered
1. **Faster R-CNN (ResNet backbone):** High accuracy, but large model size and high latency on CPU (~500ms to 1s per frame).
2. **SSD (Single Shot MultiBox Detector):** Medium accuracy, low latency, but struggles with small plastic particles/objects.
3. **YOLO Family (YOLOv8 / YOLOv9 / YOLOv10):** High accuracy, extremely low latency, excellent at detecting small objects, actively maintained, and exports seamlessly to ONNX.

### Decision
**Adopt YOLOv8 (specifically YOLOv8-nano and YOLOv8-small) as the baseline object detector.**
- We will prioritize training `YOLOv8n` for speed and low CPU footprints, and `YOLOv8s` for higher accuracy if latency permits.
- **Justification:** YOLOv8 provides a state-of-the-art balance of accuracy (mAP) and real-time efficiency. Its support for ONNX export enables deployment on standard CPUs without GPU overhead, meeting the latency criteria.

## ADR 02: Annotation Strategy for Object Detection

### Context
The PLD/PLQ dataset is organized primarily for classification, meaning it lacks bounding-box coordinates. We must convert this classification dataset into a supervised object detection dataset.

### Alternatives Considered
1. **Fully Manual Annotation:** Labeling thousands of images from scratch. Highly accurate, but extremely time-consuming and expensive.
2. **Unsupervised Object Localization (e.g., CAM/Grad-CAM):** Extracting bounding boxes from class activation maps of a trained classifier. Low effort, but bounding boxes are blurry, imprecise, and often fail to separate multiple close objects.
3. **Semi-Automated Prompt-Based Auto-Labeling:** Run a zero-shot object detector (like Grounding DINO) combined with Segment Anything Model (SAM) to generate candidate bounding boxes based on class names (e.g., "plastic bottle"). Import candidate boxes into an annotation tool (Label Studio) for manual refinement.

### Decision
**Implement a Semi-Automated Auto-Labeling pipeline (Grounding DINO + SAM) followed by human manual review.**
- **Justification:** This approach reduces active annotation time by up to 80% while preserving high label quality. Bounding box coordinates will be exported in normalized YOLO text format.

## ADR 03: Tech Stack Selection

### Context
We need a robust, scalable, and responsive application architecture to support the frontend UI, backend API, database storage, and model execution.

### Decision
- **Backend:** Python + FastAPI.
  - *Justification:* FastAPI offers native asynchronous support, autogenerated Swagger documentation, fast execution, and seamless integration with Python machine learning tools.
- **Frontend:** React + TypeScript + Tailwind CSS.
  - *Justification:* TypeScript enforces static typing, reducing runtime UI errors. Tailwind CSS allows rapid, clean, and highly styled component design.
- **Database:** PostgreSQL.
  - *Justification:* Standard relational model matching prediction-detection relations. Robust support for JSONB fields to store optional raw outputs, dynamic configurations, and future spatial queries (via PostGIS if tracking coordinates on real maps).

## ADR 04: Experiment Tracking Tool

### Context
We must track models, dataset versions, training parameters, and metrics to ensure experiment reproducibility.

### Alternatives Considered
1. **Weights & Biases (W&B):** Feature-rich cloud platform, but requires an active internet connection and API keys, creating external dependencies.
2. **MLflow:** Open-source, local-friendly, easily hosted via Docker, and handles model logging and experiment parameters efficiently.

### Decision
**Use MLflow for experiment tracking and artifact storage.**
- **Justification:** MLflow does not require cloud registration, can run locally or on a private server, and fits well into the offline development constraints of the project.

## ADR 05: Preprocessing and Image Enhancements

### Context
Water images are susceptible to reflections, glare, and low contrast (turbid water). We must decide on a preprocessing pipeline.

### Decision
**Do not hardcode preprocessing techniques without experimental verification.**
- We will implement modular pipelines including Contrast Limited Adaptive Histogram Equalization (CLAHE) and Median Filters.
- **Justification:** CLAHE is effective for underwater and surface reflection contrast enhancement, but it can occasionally introduce noise. We will run training cycles with and without these modules and log results to MLflow to measure if they improve validation mAP.
